# ADR 0001. Модульный монолит и базовый стек

**Дата:** 2026-08-04
**Статус:** принято (этап 1, ветка `feat/stage1-foundation`)

## Контекст

Новый сервис логистики для одной компании с одним складом. Нагрузка: около 200 заказов
в обычный день, более 2000 в праздничный, 50+ курьеров, регион — Москва и область.
Multi-tenant не требуется. Задание фиксирует ряд решений: TypeScript, актуальная Node LTS,
PostgreSQL 16, Prisma с forward-only миграциями, PostgreSQL-outbox, realtime через SSE
или WebSocket, Docker Compose локально, без Redis, без микросервисов и Kubernetes.

## Решение

Модульный монолит: один репозиторий, одно разворачиваемое приложение, явные границы модулей
внутри `apps/api/src/modules/`. В production один Node-процесс обслуживает API и отдаёт
собранный web-клиент.

Стек:

| Компонент | Выбор                 | Основание                                                                         |
| --------- | --------------------- | --------------------------------------------------------------------------------- |
| Runtime   | Node.js 24.19.0       | текущая LTS (Krypton); зафиксирована одинаково в `.nvmrc`, `engines`, Docker и CI |
| API       | Fastify 5             | рекомендация задания; низкие накладные расходы, встроенный pino                   |
| Клиент    | React 19 + Vite 8     | рекомендация задания                                                              |
| ORM       | Prisma 7.9.1          | см. ADR 0002                                                                      |
| БД        | PostgreSQL 16         | требование задания; хватает для outbox, очередей и rate limit без Redis           |
| Тесты     | Vitest 4 + Playwright | критические проверки и один браузерный smoke                                      |
| Пакеты    | npm workspaces        | pnpm и yarn в окружении отсутствуют, npm идёт с Node                              |

## Альтернативы

- **Микросервисы.** Отклонено: одна компания, один склад, объём данных мал. Распределённая
  система дала бы сетевые отказы, распределённые транзакции и рост стоимости без выгоды.
- **Redis для очередей и rate limit.** Отклонено заданием и по существу: PostgreSQL с
  `FOR UPDATE SKIP LOCKED` закрывает потребность, а лишний компонент — это ещё один сервис,
  который нужно резервировать, мониторить и обновлять.
- **Отдельный веб-сервер для статики.** Отклонено: один процесс проще разворачивать
  и проверять; нагрузка на статику незначительна.

## Следствия

- Горизонтальное масштабирование позже потребует вынести outbox-воркер в отдельный процесс
  и заменить in-process планировщик. Схема к этому готова: outbox использует блокировки в БД,
  а realtime-события хранятся в таблице, а не в памяти.
- Границы модулей соблюдаются дисциплиной, а не физически. Нарушение границ выявляется
  на ревью.
