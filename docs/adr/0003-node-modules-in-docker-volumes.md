# ADR 0003. Зависимости в томах Docker, а не в рабочей папке

**Дата:** 2026-08-04
**Статус:** принято (этап 1, ветка `feat/stage1-foundation`)

## Контекст

Требование проекта — Node ровно `24.19.0` с `engine-strict=true`. На машине владельца
исполняемый `node` в PATH сломан (homebrew node 25.5.0 ссылается на отсутствующую
библиотеку `libsimdjson.29.dylib`), а рабочие интерпретаторы имеют версии 24.13.0 и 22.23.2 —
ни один не соответствует зафиксированной версии. Поэтому все команды выполняются в контейнере.

Первая попытка установить зависимости в bind-mount рабочей папки на macOS не завершилась
за 9 минут и не создала ни одного файла: запись десятков тысяч мелких файлов через
файловую систему Docker Desktop чрезвычайно медленная. Путь дополнительно содержит пробелы
и кириллицу.

## Решение

`node_modules` монтируются как именованные тома Docker, а не хранятся в рабочей папке:

```yaml
volumes:
  - .:/workspace
  - app-node-modules:/workspace/node_modules
  - api-node-modules:/workspace/apps/api/node_modules
  - web-node-modules:/workspace/apps/web/node_modules
  - shared-node-modules:/workspace/packages/shared/node_modules
```

После этого установка занимает около двух минут.

Исходный код остаётся в bind-mount, поэтому правки видны сразу, а `package-lock.json`,
сгенерированный клиент Prisma и артефакты сборки пишутся в рабочую папку как обычно.

## Следствия

- Редакторы и языковые серверы на хосте не видят `node_modules` и не будут подсказывать типы
  до тех пор, пока владелец не установит Node 24.19.0 локально. Это принято осознанно:
  хостовый Node сейчас всё равно неисправен.
- Сброс зависимостей выполняется через `docker volume rm flowers-logistics_app-node-modules`,
  а не удалением папки. `docker compose down -v` удалит **и данные базы** — в документации
  эксплуатации это отмечено отдельно.
- CI не затронут: GitHub Actions работает на Linux, где bind-mount не нужен, и ставит
  зависимости обычным `npm ci`.

## Альтернативы

- **Ждать установку в bind-mount.** Отклонено: минуты ожидания на каждой операции с
  зависимостями делают работу неприемлемо медленной.
- **Чинить homebrew на машине владельца.** Не входит в задачу разработчика и не решает
  проблему скорости bind-mount.
