# app.erpget.ru на основном сервере

Это отдельное изменение входящего HTTPS, а не выпуск приложения. Не запускать
deploy-production.sh, не менять образ приложения, схему БД, очередь печати,
токены точек и processed.log/pending.json агентов. Накопленные финансовые
изменения main этим заданием в production не разрешены.

## Подготовка

1. Сохранить текущие DNS A/AAAA/TTL, Caddyfile и идентификаторы контейнеров.
2. Зафиксировать конфигурацию в GitHub и дождаться проверок точного SHA.
3. Проверить deploy/proxy/app.erpget.ru.caddy установленной версией Caddy.
   Это добавочный сайт, существующие erpget.ru/staging.erpget.ru сохраняются.
4. Получить доверенный RSA-сертификат app.erpget.ru ДО изменения рабочей A-записи:
   через DNS-01 либо согласованный HTTP-01 на прежнем прокси. Закрытый ключ
   остаётся на сервере, не попадает в Git, сообщения и журналы команд.
5. Для временно загруженного сертификата обеспечить переход к автоматическому
   продлению Caddy после переключения DNS. Ручной сертификат без продления —
   незавершённая миграция.
6. Сделать backup конфигурации, проверить весь новый Caddyfile через validate,
   применить reload (не restart). ERP, БД и геоконтейнеры не пересоздавать.

## TLS и проверка до DNS

Агенты Win7 жёстко используют app.erpget.ru. Требуются TLS 1.2, доверенная
цепочка RSA-сертификата и пересекающийся набор шифров. Шаблон сохраняет TLS 1.3
и современные AEAD-наборы, добавляя ECDHE-RSA-CBC только для app.erpget.ru.
TLS 1.0/1.1, RC4, 3DES, статический RSA и отключение проверки сертификата не нужны.
Это не обещание совместимости каждого конкретного ПК: отдельно проверить
настоящий агент Win7 перед отключением прежнего прокси.

Изолированная проверка (Node, OpenSSL и Caddy 2.11.4):

```sh
CADDY_BIN=/path/to/caddy OPENSSL_BIN=/path/to/openssl node deploy/scripts/test-legacy-proxy.mjs
```

Она поднимает только loopback-стенд с одноразовым сертификатом, явно доверенным
тестовым клиентом. Проверяет CBC/P-256, TLS 1.2/1.3, запрет старых протоколов,
изоляцию CBC от основного домена и staging, POST, Authorization и защиту от
подмены X-Forwarded-For, даже если старый прокси пока доверен глобально.
В реальный API и на принтеры запросов нет.

До DNS проверить новый адрес с сохранением SNI и проверкой сертификата
(curl --resolve), /ready, TLS из ограниченного профиля Win7, основной домен
и staging. Не выдавать 401 без токена за доказательство работы печати.

## Переключение и приёмка

Меняется только A-запись app. AAAA/CNAME, если есть, проверяются отдельно:
они не должны вести клиентов в другое место. Сохранить прежний прокси рабочим
на время DNS-кэшей; обе дороги должны вести в ту же production-БД.

Подтвердить входящие запросы агентов на новом сайте Caddy и свежие heartbeat,
сверить очередь и реальные подтверждения передачи заданий. Не создавать
повторные задания ради проверки. SENT_TO_PRINTER подтверждает приём Windows
Spooler, а не физический выход бумаги. Проверить автоматическое продление.

До выключения старого прокси требуется отдельная проверка, что все точки
перешли; спящий/выключенный компьютер нельзя объявлять проверенным.

Откат сетевого переключения — прежняя A-запись и сохранённая конфигурация.
Код и база не откатываются. Старый прокси нельзя выключать до завершения
проверки и срока DNS-кэширования.

Источники: [Caddy TLS](https://caddyserver.com/docs/caddyfile/directives/tls),
[Microsoft Windows 7 SChannel](https://learn.microsoft.com/en-us/windows/win32/secauthn/tls-cipher-suites-in-windows-7).
