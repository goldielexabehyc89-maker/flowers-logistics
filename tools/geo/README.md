# Картографические артефакты

Инструменты собирают подложку и дорожный граф из локального файла OpenStreetMap.
Ни один из них не запускается в обычном CI и не выполняется при выкатке:
московский набор — это гигабайты, скачивать которые на каждую сборку незачем
и вредно. Сборка выполняется отдельной операцией, а результат кладётся
на сервер как неизменяемый набор файлов.

## Что и чем собирается

| Артефакт                         | Инструмент | Версия                            |
| -------------------------------- | ---------- | --------------------------------- |
| PMTiles + стиль, спрайты, шрифты | planetiler | `0.10.2`, digest в `versions.env` |
| Дорожный граф                    | valhalla   | `3.8.3`, digest в `versions.env`  |

Версии закреплены в `versions.env` тегом и digest одновременно. `latest`
не используется: сборка обязана воспроизводиться через месяцы.

## Лицензии

- Данные OpenStreetMap — **ODbL 1.0**. Атрибуция «© OpenStreetMap contributors»
  обязательна и отображается на карте.
- Формат и инструменты PMTiles — **BSD**.
- Шрифты Noto Sans — **SIL Open Font License 1.1**.
- Спрайты — производные от иконок Tangram, **MIT**.
- planetiler — **Apache-2.0**, Valhalla — **MIT**.

## Вспомогательные источники

Профиль подложки использует не только `.osm.pbf`. Ему нужны три набора,
которых в выгрузке OSM нет: осевые линии озёр, водные полигоны и Natural Earth.
Без них сборка не начинается вовсе.

Готовятся они один раз — это **единственный шаг, которому нужна сеть**:

```sh
source tools/geo/versions.env
docker run --rm -v "/data/planetiler-sources:/data/sources" \
  "${PLANETILER_IMAGE}@${PLANETILER_DIGEST}" --only-download --download
```

Образ берётся тегом **и** digest из `versions.env`: один тег можно переставить
на другой образ, digest — нельзя.

Дальше каталог передаётся в сборку через `--sources`, монтируется только
на чтение, и контрольные суммы всех трёх наборов попадают в манифест: другая
их версия даёт другие тайлы, и без сумм сборку нельзя повторить и сверить.

## Лицензии в составе набора

Шрифты и спрайты отдаются браузеру с нашего origin, то есть распространяются.
И OFL 1.1, и MIT требуют, чтобы текст лицензии сопровождал распространяемые
файлы, поэтому каталог ресурсов обязан содержать:

```
licenses/fonts-OFL-1.1.txt   — лицензия Noto Sans
licenses/sprites-MIT.txt     — лицензия спрайтов (иконки Tangram)
```

Оба файла копируются в набор, попадают в манифест с размером и SHA-256
и отдаются как `text/plain`. Отсутствие любого из них останавливает сборку
до запуска Docker.

## Порядок сборки

```sh
# 1. Подложка. Файл .osm.pbf скачивается человеком заранее и в Git не кладётся.
./tools/geo/build-basemap.sh \
  --input /data/osm/central-fed-district.osm.pbf \
  --region "Центральный федеральный округ" \
  --source-date 2026-08-06 \
  --bbox 30.6998,49.5045,47.6702,59.6533 \
  --assets /data/basemap-assets \
  --assets-revision "protomaps/basemaps-assets@028c18f7" \
  --sources /data/planetiler-sources \
  --output /data/artifacts/basemap-20260806

# 2. Дорожный граф.
./tools/geo/build-valhalla-graph.sh \
  --input /data/osm/moscow.osm.pbf \
  --output /data/artifacts/valhalla-2026-08-01

# 3. Проверка перед установкой на сервер.
./tools/geo/verify-manifest.sh /data/artifacts/basemap-2026-08-01
```

Границы `--bbox` и ревизия ресурсов `--assets-revision` обязательны: значение
по умолчанию молча описало бы не тот регион и не ту версию спрайтов, а манифест
начал бы врать о содержимом архива.

Каждый набор попадает в собственный каталог с датой в имени и **никогда
не перезаписывается на месте**: приложение может читать текущий набор прямо
сейчас, а подмена файла под ним дала бы обрывок вместо тайла.

Сборка атомарна. Работа идёт во временном каталоге рядом с целевым, и только
после успешной сборки, записи манифеста и его проверки каталог переименовывается
в окончательный. Прерванная сборка не оставляет ничего, что можно принять
за готовый набор, и не занимает имя: повторить её можно по тому же пути.

## Обновление одного стиля

Оформление карты живёт в `style.mjs` и весит килобайты рядом с гигабайтом
тайлов. Пересобирать ради него весь набор незачем: `restyle-basemap.mjs`
выпускает новую редакцию стиля прямо в установленном наборе.

```sh
node tools/geo/restyle-basemap.mjs --set /srv/geo/basemap/<ревизия>
```

Что при этом гарантируется:

- архив тайлов, спрайты и шрифты не читаются на запись и остаются побайтово
  прежними; их SHA-256 в манифесте не меняется;
- имя файла не переиспользуется: `style-<ревизия>.json` → `…-r2.json` →
  `…-r3.json`. Артефакты отдаются с бессрочным кэшированием, и подмена
  содержимого под прежним именем оставила бы у части браузеров старый стиль
  на год;
- прежний файл стиля удаляется из набора и из манифеста: адресовать его
  больше некому;
- расхождение архива с манифестом останавливает обновление — чинить манифест
  под изменившийся файл инструмент не станет.

Что рисует стиль: природный покров и землепользование, охраняемые территории,
водотоки и воду, иерархию дорог из четырёх групп с обводками, железные дороги
отдельной штриховкой, административные границы, здания с 13 зума, номера домов
с 14 и подписи воды, населённых пунктов, районов и улиц. Значков POI нет
намеренно: набор иконок лежит вне репозитория, и существование конкретного
значка проверить нечем.

Структуру стиля закрепляет `style.critical.test.ts`, включая проверку
валидатором спецификации MapLibre. Но насколько карта читается на обзорном,
районном и адресном масштабах, автоматическая проверка не решает: это делается
глазами на настоящем наборе после его выпуска.

## Манифест

`manifest.json` перечисляет каждый файл с размером и SHA-256, а также регион,
границы, дату исходных данных, версии инструментов и SHA-256 входного `.osm.pbf`.
Приложение при старте пересчитывает суммы заново; несовпадение означает
«Карта не настроена», а не попытку продолжить.

## Минимальный набор для проверок

Контрактным проверкам гигабайты не нужны. `make-test-pmtiles.mjs` создаёт
крошечный, но настоящий архив PMTiles v3 без единого сетевого обращения:

```sh
node tools/geo/make-test-pmtiles.mjs /tmp/basemap
```
