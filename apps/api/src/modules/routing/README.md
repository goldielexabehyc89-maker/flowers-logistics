# Модуль `routing` — маршрутизация

**Статус: реализован частично (этапы 4.1 и 4.2).** Ручные маршруты-черновики,
их жизненный цикл и мягкая блокировка редактора.

## Что здесь есть

- `numbering.ts` — атомарная выдача номера `R-YYYY-MM-DD-NNN` через счётчик дня;
- `eligibility.ts` — чистые правила пригодности заказа и вычисление его внутреннего
  состояния из активного участия;
- `service.ts` — операции над черновиками: создание, добавление, возврат, атомарное
  перемещение между маршрутами, порядок, назначение курьера. Здесь же зафиксирован
  порядок блокировок;
- `conflicts.ts` — фиксация расхождений уже распределённого заказа. Вызывается
  синхронизацией МоегоСклада и контрольной сверкой;
- `lifecycle.ts` — подтверждение, возврат в черновик и отмена с неизменяемой историей
  переходов и повторной проверкой состава;
- `lease.ts` — мягкая блокировка редактора: захват, сердцебиение, освобождение
  и безопасный перехват;
- `routes.ts` — HTTP-слой для `ADMIN` и `LOGISTICIAN`.

## Чего здесь нет намеренно

Интерфейса маршрутов — ветка 4.3. Карт, геокодирования, расстояний и автоматического
построения — этап 5. Отгрузки, курьерских статусов, готовности склада, денег
и печатных форм — этапы 6–7.

Состояния `COMPLETED` нет: оно появится вместе с работой курьера. `ACTIVE`
добавлен этапом 6.5, но этому модулю не принадлежит: перевод выполняет склад
в транзакции выдачи последнего заказа. Здесь `ACTIVE` только читается —
возврат в черновик, отмена и смена курьера для него закрыты, как и для любого
маршрута, выдача по которому уже началась.
