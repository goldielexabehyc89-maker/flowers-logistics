# Модуль `auth` — авторизация и сессии

**Статус: реализован (этап 1, ветка `feat/stage1-auth`).**

- Вход по телефону и четырёхзначному PIN; первый вход — по одноразовому коду с установкой PIN.
- PIN и коды хранятся только как argon2id-хеш с серверным pepper. Открытые значения
  не возвращаются повторно и не попадают в логи, аудит и ответы API.
- Access-токен: JWT HS256 с TTL 10 минут, живёт в памяти клиента.
  Refresh-токен: непрозрачное случайное значение в httpOnly cookie на пути `/api/auth`.
- Ротация refresh сериализуется блокировкой строк семьи. Внутри grace-окна (30 с) повтор
  возвращает того же преемника; после окна или если преемник уже ротировался — это
  повторное использование, вся семья отзывается, событие пишется в аудит.
- Прогрессивная блокировка перебора в PostgreSQL, отдельно по телефону и IP:
  3 → 30 с, 5 → 5 мин, 7 → 30 мин, 10+ → 2 ч. Успешный вход сбрасывает счётчики.
- Неизвестный телефон проходит проверку с заранее подготовленным хешем-пустышкой,
  чтобы его нельзя было отличить по времени ответа.
- Заморозка, сброс PIN, смена телефона или ролей и выход со всех устройств увеличивают
  `sessionVersion` и закрывают доступ немедленно, не дожидаясь истечения access-токена.

Файлы: `crypto.ts`, `tokens.ts`, `sessions.ts`, `lockout.ts`, `service.ts`, `guards.ts`,
`routes.ts`, `bootstrap.ts`.
