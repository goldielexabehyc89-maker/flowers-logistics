# Локальный обработчик печати

Серверная половина автоматической печати бланков (`docs/OWNER_DECISIONS.md`,
`FUL-010`). Клиентская половина — `apps/print-agent`.

## Что здесь есть и чего здесь нет

Здесь **нет второй очереди печати**. `OrderPrintForm`, `OrderPrintJob` и
`PrintJobState` остаются единственными и живут в `modules/fulfillment`. Этот
модуль добавляет к очереди не хранилище, а протокол: забрать задание,
отчитаться об этапе, подтвердить исход. PDF собирает тот же генератор
(`fulfillment/pdf.ts`) из того же неизменяемого снимка.

## Два контура, которые не пересекаются

|               | `/api/print-agent/*`              | `/api/settings/print/*`                 |
| ------------- | --------------------------------- | --------------------------------------- |
| Кто           | компьютер                         | человек                                 |
| Охрана        | `authenticateDevice` (`guard.ts`) | `authenticateWithRoles`, только `ADMIN` |
| Секрет        | токен устройства, SHA-256 в базе  | пользовательский JWT                    |
| Что открывает | только свои задания печати        | реестр устройств и действия над ними    |

Пользовательский JWT не является токеном устройства, и наоборот. Специальной
проверки «а не JWT ли это» в охране нет намеренно — она была бы вторым,
расходящимся со временем описанием того же правила. Хватает того, что SHA-256
чужого значения не встречается в `PrintAgentDevice.tokenHash`, а токен
устройства не несёт подписи и `verifyAccessToken` вернёт по нему `null`.

`ActivationCode` **не переиспользуется**: он привязан к человеку и активирует
учётную запись с ролями. Компьютер с ролями человека видел бы заказы,
пользователей и настройки.

## Порядок отчётов — это и есть защита от двойной печати

Обработчик обязан сообщить `printing` **до** передачи документа драйверу.
Отсюда однозначность состояний:

- `CLAIMED` — принтер документа не видел. Безопасно вернуть в очередь;
  зависшее `CLAIMED` возвращается автоматически.
- `PRINTING` — документ у драйвера, исход неизвестен. **В очередь не
  возвращается никогда и ни по какому таймеру**, только человеку
  (`NEEDS_REVIEW`).

Если бы отчёт шёл после передачи, оба состояния значили бы «может быть,
напечатано», и различить их было бы нечем.

## Инварианты держит база

Проверка в коде здесь не годится: два одновременных запроса прошли бы обе
проверки. См. `prisma/migrations/20260825090000_florist_print_agent`.

- Ровно один основной обработчик: уникальный индекс по `primaryKey` плюс CHECK
  на само значение и на то, что отозванный основным не бывает.
- Не более одного активного кода привязки во всей системе: тот же приём, что у
  `ActivationCode`, но область — система, поэтому `activeKey` постоянен.
  Именно единственность активной строки и позволяет хранить код Argon2id-хешем,
  который принципиально неискуем.
- Вид документа определяет обязательность заказа, снимка и номера попытки.
- «Напечатано» именное: автором признаётся либо человек, либо устройство.

## Секреты

- Код привязки: 8 знаков, 10 минут, одноразовый, Argon2id с **отдельным**
  pepper `PRINT_AGENT_PAIRING_PEPPER`. Открытый текст выдаётся один раз
  с `Cache-Control: no-store`, в аудит и журналы не попадает.
- Токен устройства: 32 случайных байта с префиксом `flpa_` (он же ловится
  `.gitleaks.toml`), в базе только SHA-256.
- Перебор кода останавливает `AuthLockout` с пространством имён `print-pair:` —
  отдельно по адресу и по системе. Выпуск нового кода сбрасывает общий счётчик:
  он защищает конкретный секрет, и попытки против отменённого кода к новому
  отношения не имеют.

## Ручная печать не сломана

Отметка «Напечатано» человеком остаётся штатным запасным режимом и доступна в
том числе для заданий, зависших у обработчика: `NEEDS_REVIEW` — это ровно
вопрос «вышел ли бланк», и ответить на него может только тот, кто посмотрел
в лоток. Браузерная печать остаётся запасным вариантом.
