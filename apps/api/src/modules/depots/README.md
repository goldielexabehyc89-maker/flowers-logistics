# Модуль `depots` — склады

Ветка 5.4. Склад — предметная сущность, а не настройка: его координаты
участвуют в маршрутах, матрицах и неизменяемой истории планирования.

## Инвариант

Складов по умолчанию **не больше одного**, и он **всегда активен**. Держится
тремя независимыми средствами:

1. уникальный индекс по `defaultKey` — «не более одного»;
2. `CHECK Depot_default_active` — «выключен и по умолчанию» невозможно;
3. выделенная advisory-блокировка `DEPOT_LOCK_KEY = 730206` на создание,
   смену умолчания и деактивацию.

## Смена склада по умолчанию

Принимает **тождество и версию прежнего** склада и версию нового. Одной версии
мало: номера версий разных строк независимы и совпадают случайно, а совпавшая
версия чужого склада пропустила бы смену, которой клиент не видел.

Версии обеих строк увеличиваются. Если назначение нового умолчания не обновило
ни одной строки, транзакция завершается **ошибкой**: снятие прежнего признака
откатывается вместе с ней, и система не остаётся вовсе без склада по умолчанию.

Первый склад становится складом по умолчанию **в той же транзакции**, в которой
создаётся.

## Удаление

Склады не удаляются никогда — триггер `depot_no_delete`. Недоступность
выражается признаком `isActive`.

## Права

- чтение — `ADMIN` и `LOGISTICIAN`;
- создание, изменение, активация и выбор склада по умолчанию — только `ADMIN`.
