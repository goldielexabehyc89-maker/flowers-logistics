# Модуль `settings` — системные настройки

Ветка 5.4. Версионируемые несекретные настройки планирования. Токены и ключи
интеграций сюда не попадают никогда: они живут в переменных окружения.

Хранение — `SystemSetting`: история версий и ровно одна текущая на ключ
(частичный признак `currentKey`). Прежняя версия не переписывается.

## Ключи

- `planning.shift` — начало и окончание общей смены, минуты от полуночи.
  **Обязательна, умолчания не имеет.** Придуманный рабочий день — это придуманные
  временные окна и придуманный план: система, решившая за логиста, что курьеры
  работают с девяти до шести, построила бы правдоподобный и неверный маршрут.
  Пока администратор её не сохранил, планирование отвечает `SHIFT_NOT_CONFIGURED`.

- `planning.serviceTime` — время обслуживания по типу транспорта. Умолчание есть:
  десять минут **на заказ** для автомобиля и десять для пешего курьера. Ошибка
  здесь не меняет состав маршрута, а лишь слегка смещает расчётное время.
  На заказ, а не на уникальную точку: два заказа в одном подъезде — это два
  вручения.

Фактически использованные значения попадают в неизменяемый снимок входа
планирования: настройка меняется, и без снимка повторный расчёт того же дня дал
бы другой ответ.

## Интерфейс

Обе настройки и склады редактируются формами в разделе «Настройки»
(`apps/web/src/screens/settings/PlanningSettings.tsx`). Обязательное условие,
настраиваемое только запросом к API, не настроено по-настоящему.

## Права

Читают `ADMIN` и `LOGISTICIAN` — логист должен понимать, из чего сложился план.
Меняет только `ADMIN`.
